## What it is

~45–53 active paying users. App is FREE to download; subscriptions (Basic/Pro/Master)
bayad manually via Wise + Telegram, LABAS ng Google Play. Free tier = cap-limited

`src/App.tsx` (~4.3k lines); pure/testable logic is extracted to `src/lib/*`
(`orderLogic.ts`, `dateHelpers.ts`, `slipFields.ts`, …).

## ⚠️ DEPLOYMENT MODEL — read before shipping anything
**The APK is a THIN SHELL.** `mobile/capacitor.config.ts` hard-codes
`server.url = https://www.sellerflowlive.com/...`, so the running app = whatever
**production** (Vercel `main`) serves.
- ✅ **FRONTEND changes** (`src/App.tsx`, `src/db.ts`, `src/lib/*`, timezone
  strings) → merge to `main` → Vercel deploy → **live on web AND APK instantly,
  NO APK rebuild.**
- 🔧 **NATIVE changes** (`TsplBuilder.java`, Swift plugin, ESC/POS, mipmaps,
  Capacitor config) → **APK rebuild + Telegram distribution.** CI can't build these.
- **TSPL goldens** (`src/lib/__tests__/tspl.test.ts` vs `tsplReference.ts`) are
  regenerated by a **JVM** tool (`mobile/ios/tspl-parity/`, Mac/`run.sh`). A
  native sticker change leaves **CI red until goldens are regenerated**.
- **Preview URLs cannot TikTok-connect** (Render `CLIENT_ORIGIN=sellerflowlive.com`),
  so live-order flows can only be tested on production.

### Rollback (production)
- **Fastest (no rebuild):** Vercel → Deployments → previous production deploy →
  **Instant Rollback / Promote to Production**.
- **Git:** `git push origin <prev-sha>:main --force` → Vercel redeploys it.

## ⚠️ Critical rules — WAG GALAWIN
- **billing `orders` ledger** (~31k rows) + its `check_and_increment_free_order`

- **`live_session_orders`** table = SEPARATE sa billing ledger. RLS 4 policies
  `user_id=auth.uid()`, keyed per `user_id`+`session_date` (Taipei).

- **`orderNum` = epoch ms (>1e12)** — the BT sticker pipeline derives Taiwan
  local time from it; `rebuildSessionFromRows` preserves this.

  (sira ang TikTok kung i-force).

### Language-agnostic buyer names (`writeTextSmart`, 3-tier, all 3 builders; commit acf4abd)
Name is arbitrary buyer data (public app → any language). Decided on the
transliterated name, no per-language special-casing:
1. **Latin** (English/Filipino/Indonesian/Vietnamese/European): `transliterateLatin()`
   NFD-strips accents + atomic map (đ Đ ł Ł ø Ø æ Æ œ Œ ß þ ð ı) → big ASCII font "4" (32).
2. **CJK** (Chinese/kanji): `TSS24.BF2` enlarged 2× (48) on ALL sizes via relative
   shift (`extra = nameCjkGap − nameGap`, only when CJK → English byte-identical,
   order row preserved).
3. **Unsupported** (Arabic/Korean/Thai/…): `@handle` if ASCII, else OMIT name line.
   Buyer # + price code ALWAYS print (never "?").
- ⚠️ **HARDWARE:** AIMO D520BT renders **ASCII + Simplified Chinese ONLY**; others
  rely on the fallback above.

## Cross-device live session (Supabase + frontend, NEW)
Lets a seller open today's session on a second device / after refresh/logout and
see the same buyers + orders. Fixes data-loss + "reset to #1" complaints.
- **Table `live_session_orders`** (cols: `id, user_id, session_date(date),
  buyer_number, handle, customer_name, platform, product, price, created_at`).
- **Write:** `saveLiveSessionOrder()` (`src/db.ts`) — one INSERT on 1-click, inside
  the existing `Promise.all` in `createOrderFromComment`.
- **Read:** `loadTodaysLiveSession()` on open/login; `rebuildSessionFromRows()`
  (`src/lib/orderLogic.ts`, pure + unit-tested) rebuilds `{buyers, orders}`. LOAD
  effect hydrates **only when local session is empty** → never clobbers the active
  selling device.
- ⚠️ **ZERO POLL** — write-on-1click + read-on-load only.
- Keyed per `user_id` + **Asia/Taipei** `session_date` (`currentLiveDayId` unified
  from device-local `liveDayId()` to `taipeiDayId()` so write/read share one bucket).
- **23:59 reset = date-filter, NO cron** — `loadTodaysLiveSession` filters
  `session_date = today(Taipei)`; yesterday's rows fall outside → fresh #1.
  ✅ **VERIFIED:** 06-22 had #1–54, 06-23 started fresh #1–16.

### Key learnings (load-bearing)
- **Asset/file transfer Mac ↔ remote Claude Code = GIT BRIDGE** (`cp` on Mac →
  push → pull/Vercel), OR GitHub web upload. **Drag-drop into chat does NOT
  reach the remote container** (no access to the Mac's `~/Downloads`).
- **`auth.users.updated_at` is NOT reliable** for detecting an admin-initiated
  change — it also bumps on normal user login. Use `admin_password_log` for the
  audit trail instead.
