Picture failure → today's HTML + `getLastOneStickerWebMiss()`.
- **Custom size:** W and H 30–110 mm. All image paths take any W×H with NO native change (D520 `SIZE`, TSPL `SIZE/GAP`, ESC/POS raster, CPCL page height, Niimbot `labelWidthMm/HeightMm` read by both native drivers). Hidden on the TEXT path (old app / Classic) and WiFi (P7/P8 are Branch 2).
- **Readability guard (Jeff, 2026-11-07; `oneStickerReadable.ts`, `readableStyle` in oneStickerText):** each printed line is compared with the same text in Normal without ink at the SAME size: (a) letter by letter — every real counter of the Normal letter (bigger than a pinhole of max(3, px²/400) dots) must still have open white IN THE SAME PLACE (overlap ≥ min(30 %, px²/150 dots)), and no letter may have fewer pieces of ink (strokes run together); (b) pair by pair — two neighbouring letters may not touch where they sit on the line, unless the Normal font itself joins them at its own printed spacing (so "rn" never prints as "m", "vv" never as "w"). Anything closes → that line prints one step lighter: first without the 1-dot ink, then Extra → Bold → Normal (ink first, then without). The decision is CONFIRMED on the exact lines that print (after a wrap or a "…"); a printed line that still closes → lighter, laid out again. Never bigger or smaller: the comment's size (its shrink-to-fit) is decided with the seller's own weight, the lighter weight is applied after at that same size, and every line's height is measured with the chosen weight, so a lighter line never moves the lines below (test: every size × scale 1/1.5/2 × long Chinese/Japanese; CJK name + Extra + comment ×2 on Niimbot / TSPL / D520). Cached per letter and per letter pair (first print of a new comment ≈ 75 ms in tests). The preview uses the same function (preview = print); the saved setting is unchanged; no message. ### §1c — ONE PRINTER LANE + FINAL SAFETY on the real bytes (Nov 9 2026 — XP-420B extra blank labels)
- **Why:** Jeff, iPhone → Xprinter XP-420B 60×40, QR on, admin language test on the new sticker: blank labels
  between stickers, moving between languages from run to run (Niimbot never). Captured in a real browser
  (Playwright Chromium; WebKit is not installed in the build container), every admin sample × every size ×
  QR on/off, new sticker AND today's: **every job is the same 8 commands as today's sticker**
  `SIZE 60 mm, 40 mm · GAP 2 mm, 0 · DIRECTION 1 · REFERENCE 0,0 · SPEED 4 · DENSITY 15 · CLS · (BITMAP bands) · PRINT 1`,
  no FEED / FORMFEED / HOME / GAPDETECT, one PRINT, every band inside the 480×320 label (lowest band ends at
  dot 301, lowest ink ≤ 300). The bytes were never the cause.
- **Cause found (JS):** the order queue (`enqueueNativeSticker`) waited one job at a time, but Printer Test,
  the admin language test (`printOneStickerTest`) and Printer Settings / Print Pattern test
  (`printStickerBtRouted`) went to the printer DIRECTLY — a test tapped while another sticker was still
  sending started a second BLE job. **Fix:** `onPrinterLane(fn)` in printing.ts — orders, Printer Test, the
  admin language test and Printer Settings test now run one at a time in tap order on the phone's printer;
  a job that never settles frees the lane after the same 35 s watchdog as the order queue. An idle lane
  starts the job synchronously (byte- and timing-identical to before for a single print).
- **Final safety:** `adapters/stickerJobGuard.ts` (pure) checks the REAL bytes right before each send —
  TSPL (Flash Y41BT, XP-420B), D520 SDK stream, generic ESC/POS, generic CPCL, Niimbot image vs the SDK frame,
  laptop picture vs the W×H mm page: SIZE = the label, never taller than the label, exactly ONE print, no
  feed / re-sync command, no band past the end. A job that fails is **not sent** (the print reports
  `STICKER_JOB_INVALID`, a `[STICKER-GUARD]` log; laptop falls back to today's page). The encoders never
  make such a job — this is the backstop. Valid jobs pass through untouched (bytes identical).
- **Not changed (native, needs a new binary to change):** iOS/Android generic BLE connects per job, writes
